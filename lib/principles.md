# Core Principles (cross-cutting)

Operating rules that apply across every wk skill. Narration discipline and the em-dash prohibition live in `lib/narration.md`.

1. **One branch, one ticket.** All work happens on a single feature branch. Stages that produce real code commit it as they go, one commit per step (not one commit at the end of the stage): each test-writer/code-writer/review-fix step gets its own commit, so a regression can be traced to the exact step that introduced it. Stages whose only output is `.doer/` do not commit. The wrapup squash collapses everything into one PR-ready commit before the team ever sees it.
2. **Delta-aware reviewers.** After iteration 1, reviewers receive prior findings plus the latest changelog entries inline; they verify fixes and scan touched lines, never re-analyze from scratch.
3. **Bounded loops.** The build loop caps at 3 iterations. If it has not converged, the dev decides.
4. **Lessons accumulate.** Every ticket captures what went well and what did not, into the global pool at `${CLAUDE_PLUGIN_ROOT}/lessons/`. Future tickets read the applicable ones before planning.
5. **No hidden state.** Everything the orchestrator knows lives on disk under `./.doer/`. Closing the session is pausing; context compaction never loses progress.
6. **All commits use `git commit --no-verify`.** Pre-commit hooks interrupt mid-stage without value (intermediate states may fail a hook while correct for the stage). The dev runs the real checks manually before the PR. The orchestrator never pushes.
7. **`.doer/` NEVER reaches the team's git history.** Non-negotiable. Intake adds `.doer/` to `.git/info/exclude` (per-clone, never committed). Commits use `git add <paths>` or `git add -A` (respects the exclude); NEVER `git add .doer/...`. Wrapup verifies and, if needed, rewrites history to scrub it.
8. **No fix without root cause.** Any agent responding to a failing test or broken behavior follows `lib/debugging.md` before touching code.
9. **Em-dashes prohibited** in every output and artifact. See `lib/narration.md`.
10. **Internal orchestration vocabulary NEVER reaches team-facing artifacts.** Non-negotiable. Forbidden in committed code, commit messages, and PR descriptions: `AC-N` labels; the `PROTOLOG` / `PROTOLOG_RESPONSE` / `REPLAY` / `DOER` log tags; stage or loop names ("Stage 3", "iter 2", "the reviewer"); the literal word `doer`; ticket numbers dragged in from unrelated contexts. Translate `AC-N` to the behavior it describes (from `metadata.ac.in_scope`) before inlining anything into a writer prompt, and grep-validate every generated team-facing artifact before presenting it. Note the regex subtlety: `\bPROTOLOG\b` does NOT match `PROTOLOG_RESPONSE` (`_` is a word character, so there is no boundary after `G`), so a validation grep must use a bare `PROTOLOG` (no trailing `\b`) or an explicit `PROTOLOG_RESPONSE|REPLAY` alternation to catch both tags; see `skills/bugfix/SKILL.md` Stage 6 step 7 and `skills/doer/stages/05-wrapup.md` step 5 for the corrected pattern. The internal per-stage commit prefix `doer(<TICKET-ID>):` is exempt because those commits are squashed away using the recommended message before the team ever sees them.
